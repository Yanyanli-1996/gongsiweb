# 材质特性文案库

家具材质库：36 种材质 × 12 个品类大类，每种材质一张卡，标注适用品类 + 特性标签 + AI 文案。

**GitHub 仓库**：[Yanyanli-1996/gongsiweb](https://github.com/Yanyanli-1996/gongsiweb)

**GitHub Pages 地址**：https://yanyanli-1996.github.io/gongsiweb/ （首次部署成功后启用）

**原云服务站点**：https://material-kb.app.workbuddy.host/

## 编辑和自动发布

项目仍是纯 HTML / CSS / JavaScript，不需要前端框架。Node.js 22+ 只用于预览、检查和打包。

```bash
npm ci
npm run dev
```

打开 http://127.0.0.1:8080 ，编辑 `app/` 下的文件，保存后刷新即可看到变化。

修改完成后提交并推送：

```bash
npm run check
npm test
git add app scripts tests .github README.md package.json package-lock.json playwright.config.js .gitignore
git commit -m "更新材质文案库"
git push origin main
```

每次推送 `main`，GitHub Actions 自动运行语法检查、数据检查、单元测试、浏览器测试，然后把 `app/` 部署到 GitHub Pages。只有检查通过才发布。部署进度在仓库的 Actions 页面查看；线上更新需要等待部署完成，页面内的数据编辑保存到 WorkBuddy 云数据库，与代码提交是两套流程。

首次发布需在仓库 Settings → Pages → Source 选择 **GitHub Actions**。已有代码的其他设备先 `git pull --rebase` 再继续修改，避免覆盖远端变更。

### 云服务和快照

- 读取云端前立即显示仓库内的 36 张卡片快照；成功读取后更新为云端内容。
- 云端不可用时可以搜索、筛选、复制和导出；快照只读，避免误以为修改已经同步。
- 云端保存成功才结束编辑；保存失败保留草稿并提示，刷新页面前请先完成保存。
- `data/material_notes-快照.json` 是备份快照，修改后执行 `npm run snapshot` 更新前端文件。它不会自动跟随云数据库变化。
- 页面中的云服务配置包含供浏览器使用的 publishable key；真正的数据访问权限应由云服务端控制。迁移后需确认新域名的跨域和来源配置。

## 一、这个项目做了什么

把零散的商品素材，整理成一套**可检索的材质知识库**：

- 1052 条原始识别记录 → **合并去重 → 36 张卡（每材质一张）**
- 每张卡标注**适用哪些品类**（平均 5 个）
- 每张卡带 **AI 重写的卖点文案**（3 条）+ 三行卖点（场景/痛点/优势）
- 支持按「品类 → 材质 → 特性标签 → 关键词」四层筛选

## 二、核心设计原则

### 1. 品类 ≠ 材质

- **品类**：柜类、桌、椅、凳、床、沙发、茶几、餐桌、床垫、床品、衣帽架、功能件（12 大类）
- **材质**：橡木、黑胡桃木、头层牛皮、半青皮、雪尼尔、岩板……（36 种）

同一品类可以有多种材质。筛选「床」时，8 种木种 + 5 种皮 + 布料 + 海绵全部出现。

### 2. 一材质一卡，一卡多品类

36 张卡 = 36 种材质。每张卡的 `raw_text.appliesTo` 存适用品类列表。

### 3. 只展示具体材质

「实木」「板材」「其他」这类泛称**不出现在卡上**，必须落到具体品类：

| 泛称 | 拆分为 |
|---|---|
| 真皮 | 头层牛皮（修饰完整）/ 半青皮（修饰更少，保留天然毛孔） |
| 实木 | 橡木、黑胡桃木、白蜡木、水曲柳、榉木、楸木、松木、橡胶木 |
| 板材 | E0级板材、ENF级板材、颗粒板 |
| 其他 | 仿真皮、硅胶、金属、毛毡、PET、羽丝绒 |

### 4. 标签只留材质特性

删掉：规格尺寸、风格、颜色、认证背书、促销服务、空间场景。
保留：材质本体、触感、性能、功能。

## 五、两个核心文件

### `app/mat-profile.js` — 材质特征库

40 种材质，每种定义：

```js
'雪尼尔': {
  kind: '软包面料',        // 大类
  alias: ['雪尼绒'],       // 别名（归一化用）
  feat: '软包面料，手感好，有绒感/凹凸质感',   // 固有特点
  facets: ['软包面料','手感好','有绒感','凹凸质感'],  // 细分标签
  scene: '...', pain: '...', sell: '...'   // 三行卖点
}
```

改这里就能调整某个材性的特点描述。

### `app/kb-matcat.js` — 品类×材质规则

```js
MAT_KIND: { '橡木':'木质', '头层牛皮':'皮面', '雪尼尔':'布料', ... }
CAT_KIND: { '柜类':'硬体', '沙发':'软体', '床垫':'床垫', ... }
canApply(材质大类, 品类大类)  // 判断能否搭配
excluded(材质大类, 品类)      // 排除不合理组合
```

改这里能调整「哪些材质能用于哪些品类」。

## 七、维护提示

1. **改材质特点** → 编辑 `app/mat-profile.js`
2. **改品类归并** → 编辑 `app/kb-cat.js` 的 `CAT_MAP`
3. **改材质×品类规则** → 编辑 `app/kb-matcat.js`
4. **改标签体系** → 编辑 `app/tags-data.js`（含 `groupOrder` 品类清单）
5. **改完先自检**：`npm run check && npm test`；完整页面检查：`npm run test:browser`
